# 技术 RFC 写作

交付可评审、可实施、可验证的技术提案。读者应能据此判断：问题是否成立、推荐方案为何成立、接受哪些代价、如何验证与落地。

## 写作契约

- **精简表达，保留必要信息。** 删除套话、重复背景、空泛形容词和图文复述；保留约束、机制、边界、失败路径、兼容性和验证条件。不以字数少、章节少或固定页数为目标。
- **用证据支撑判断。** 区分已观察事实、假设、估算、目标与推荐。关键结论旁给出可追溯来源或推导；没有数据时说明未知和验证方法，不编造基线、收益、测试结果、负责人或时间承诺。
- **明确推荐及其代价。** 可以提出主张，也应指出用户设想与证据的冲突。把“更优雅、显著提升、无缝、易扩展”等评价改为具体行为、适用条件和成本；不要把主观偏好伪装成共识。
- **用同一个案例贯穿。** 从现状的问题输入，走到方案行为、异常分支和验收；比较前后或不同方案时使用相同条件。
- **视觉承担信息。** 主动为跨组件关系、执行顺序、状态变化、数据差异选择图示；图中呈现文字难以直观看到的关系。简单到一句话即可说明的改动无需配图，不设最低图数或图文比例。

## 工作方式

### 1. 明确任务与证据

从用户材料和现有项目中确定：待决策事项、评审读者、范围、约束、交付位置及已有模板。沿用用户语言和目标文档平台；未指定时采用便于维护的 Markdown。遵循用户要求的保存或对话交付方式，写作本身不授权发布、群发或变更业务系统。

优先读取相关代码、接口、测试、日志、数据和已有决策；外部引用查阅原始文档。将会改变核心方案的缺失信息列为待确认，同时完成能够确定的部分。仅当答案实质影响设计时提问，不因缺少次要信息停写。

对重要主张区分其状态，不要求每句话加标签：

| 状态 | 写法 |
| --- | --- |
| 已观察事实 | 描述条件、结果和来源；测量还需版本、环境、方法与单位。 |
| 假设或估算 | 说明依据、适用条件、主要不确定性和验证方式。 |
| 验收目标 | 明确是期望达到的标准；未获确认的阈值标为建议值。 |
| 推荐决策 | 写出选择标准、理由、接受的缺点及可能推翻结论的条件。 |

### 2. 组织论证

起草新 RFC 时读取并裁剪 [RFC 模板](assets/rfc-template.md)。修改现有文档时保留有效结构，只补充缺失的决策信息。不要机械生成所有章节、空表格或大量“无／不适用”。

正文应让读者找到以下内容，可合并或按需展开：

- 决策摘要与问题证据；问题描述应允许其他人提出不同解法。
- 目标、非目标、约束和一个具体的使用前后对照。
- 方案概览，以及支持实现的接口、数据流、规则和异常行为。
- 关键取舍：可行备选方案与维持现状，按相同标准比较；记录选择依据和未解决的冲突。
- 验证计划；涉及现有使用者或运行系统时，补齐兼容、迁移、发布、观测和回退。
- 开放问题：区分决策前必须解决、实现中验证和明确延期；重大未知项不要藏进附录。

先解释使用者看到的行为，再展开实现规则，并使规则与前文示例对应。完整 API 清单、长日志和细节推导可放附录，关键限制和反例留在正文。需要借鉴写法时按问题读取 [社区范例](references/community-patterns.md)，无需每次通读外部 RFC。

### 3. 制作有用的视觉材料

涉及多方协作、并发、生命周期或体验变化时，读取 [视觉与动态演示指南](references/visual-guide.md)，选择并实际制作能降低理解成本的图或演示，不只留下“此处放图”。

- 关系、边界、顺序与状态优先使用可维护的 Mermaid 或矢量图；数据使用可复现的绘图工具；实际界面使用真实截图或录屏。
- 图、正文、代码中的术语和条件保持一致。每幅图附简短说明，指出结论、关键条件或省略范围；正文解释图中无法充分表达的原因和例外。
- GIF／视频用于时间、动作或交互本身构成论据的情况。区分真实录制、原型演示和概念动画，并保留静态图或文字回退。
- 根据当前可用工具制作；不要求安装特定付费服务。不具备录制或渲染条件时，交付可读的静态表达或明确标注的分镜／演示步骤，说明未完成项，不伪称已生成或已验证。

### 4. 编辑与验证

完成后按决策需要检查，发现问题直接修订：

1. **论证：** 关键判断是否有证据或明确假设？是否公平比较可行替代方案？已拒绝的方案与延期研究是否分开？
2. **完整性：** 涉及的边界、失败、兼容、成本和验收是否足以评审？核心未知项是否显露？
3. **表达：** 每段是否提供新信息？删除评价性套话，合并重复内容，保留必要解释；不用术语堆叠代替论证。
4. **视觉：** 实际渲染检查图的方向、标签、布局和可读性；播放已生成的动态媒体，核对顺序、字幕与真实条件。不能预览时明确说明限制。
5. **交付：** 检查引用、相对路径和媒体链接，保留可编辑源文件及需要的静态回退；完成文档中不留指导性占位符。尚未确定的设计内容应变成明确的开放问题。

评审任务先报告影响决策的证据缺口、矛盾和遗漏，再给具体修改；不要因为章节不齐或没有 GIF 就判定不合格。交付时提供文档与媒体入口、仍待决策的问题和实际验证情况。
