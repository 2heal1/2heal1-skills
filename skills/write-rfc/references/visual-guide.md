# RFC 视觉与动态演示

根据读者需要理解的信息选择材料，替换密集文字时遵循 [表达与材料](../SKILL.md#4-表达与材料)。本指南负责选型、制作和视觉检查。

## 选型

| 需要理解的内容 | 优先表达 | 必要信息 |
| --- | --- | --- |
| 模块职责与系统边界 | 架构图／组件图 | 参与方、边界、方向和数据，区分现有与新增。 |
| 请求、异步协作、并发与错误恢复 | 时序图 | 触发条件、先后关系、并行区间和失败分支。 |
| 生命周期与资源归属 | 状态图 | 状态、迁移条件、终止与恢复路径。 |
| 接口、配置与具体输入输出 | 类型／配置／数据示例 | 关键字段和对应关系，区分现有接口与已定义的设计提案。 |
| 条件、例外、兼容范围与方案差异 | 表格／矩阵 | 每行一项可比较的规则，列明结果、适用条件与限制。 |
| 使用或迁移前后变化 | 对照代码／截图／差异表 | 相同输入和环境下发生的变化。 |
| 延迟、吞吐与资源关系 | 数据图表 | 来源、单位、轴、统计口径和不确定性。 |
| 时间、动作或交互本身构成论据 | GIF／视频／关键帧 | 操作、等待、反馈和演示条件。 |

一张图聚焦一个问题，必要时分为总览与局部详图。图、正文、代码保持相同的名称、条件与行为。

## 制作与图注

- 结构和时序优先 Mermaid，需要精确布局时使用矢量图。数据图使用真实数据与可复现绘图工具，实际界面使用真实截图或录屏。工具服从目标平台与现有环境，不要求特定付费服务。
- **本地默认风格：** 白底、细线、克制的颜色与简洁图标。时序图使用横向参与方、虚线生命线、细箭头和活动条，参考用户偏好的 [Cloudflare 配图](https://blog.cloudflare.com/fragment-piercing/#how-it-works)。按信息结构调整，用户指定的风格优先。
- 精确架构、协议、代码、日志和基准图不交给生成式图片工具自由编造。原型或概念图容易被误认成真实界面、实测或已实现行为时，明确其性质。
- 图注只补充读图必需的条件或结论，不逐项复述节点，也不机械添加“非性能测量”等说明。
- 用标签、线型或形状表达含义，颜色只作辅助。最终阅读尺寸下文字应可辨，提供简短替代文本。截图保留影响判断的信息。

## GIF 与视频

仅当时间、动作或交互影响判断时使用动态演示。制作时：

1. 确定要证明的变化及输入、操作和起止状态。比较时保持数据、设备、网络与操作可比。
2. 有真实实现时录制。只有设计时用概念动画、原型或分镜，并在可能误认时标明。动画不能证明性能收益或生产可靠性。
3. 用短分镜保留关键操作、等待、错误和反馈。GIF 适合短循环，较长过程使用可暂停视频。标明加速、剪辑或模拟延时，不为演示擅自触发业务写入。
4. 提供静态关键帧或时序图，使关键结论不依赖播放、声音或外链。保留复现所需的条件、输入和资源。

无法录制或渲染时，交付可读的静态表达或明确标注的分镜，说明未完成项，不嵌入不存在的媒体。

## 视觉检查

- 查看实际渲染，核对箭头、分支、标签、重叠、裁切、字号和对比度。动态媒体还需播放检查顺序、字幕与循环衔接，不能把源码审阅称为视觉验证。
- 目标平台不支持 Mermaid／SVG 时导出兼容图片，保留可编辑源文件。展示资源使用平台支持的路径或附件引用，确保文件存在且可访问。
- 格式转换后按 [复核与交付](../SKILL.md#5-复核与交付) 回读。无法预览的项目明确说明，不宣称已验证。
